Module 04 · Self-hosted model · 2026-10-13

We ran our case studies again on one rented GPU, with no frontier model in the agent's seat.

Every earlier study ran NeoDevEx on Google's Gemini models, billed per token. This time the agent ran on Qwen3-Coder-Next, an open-weight (Apache-2.0) coding model, served by vLLM on one RTX PRO 6000 GPU rented from Runpod for $1.69 an hour. We changed nothing else: same tasks, same app settings, same graders, and the same Gemini or Claude judges where the original studies used them. The result is mixed, and we report it that way. On a flat-rate GPU the four studies cost about $4 in total. Against what Gemini actually charged in the original runs that saves at least $10, almost all of it in the KT docs study; for chat and the token benchmark the two roughly break even. The same tokens at Gemini list prices with no caching would have cost $23 (2.5 Flash) to $146 (4 Argon), but Gemini uses far fewer tokens and caches, so that is an upper bound. The self-hosted model wrote the best tests NeoDevEx has scored, and it passed more token-bench tasks than Gemini on the same settings. It was weaker at explaining code and writing docs, much slower, and in automations it twice pushed straight to main and once created a GitHub repository nobody asked for.

What it cost, GPU by the hour against Gemini by the token

Token counts come from the model server for every call. Gemini prices are Google's paid list prices on 2026-10-13 (the table in our chat study's summarize.py).

The per-study GPU shares overlap because the studies ran at the same time on one GPU, so they add up to more than the time actually billed. Measured Gemini costs alone come to at least $14.67 on Flash and at least $17.05 on Argon, against $4.80 billed for Qwen, so the saving is at least $10 against Flash and at least $12 against Argon. Almost all of it comes from the KT docs study, where Gemini cost $13.27 and Qwen about $1.47. For chat and the token benchmark the two roughly break even. The GPU stopped itself after an hour of uptime each time, so an idle GPU could not keep billing; the disk keeps billing at about $1 a day until the pod is deleted.

What went wrong

  • AUTOMATIONSTold to work in a repository that does not exist, the agent deleted its clone's .git, ran gh repo create and made the repository instead of reporting the error. Gemini and Devin both reported it.
  • AUTOMATIONSTwice it pushed commits straight to main instead of opening a pull request: the changelog task, and an issue reply that was meant to stop after replying. It also opened two fix PRs nobody asked for.
  • AUTOMATIONSTwo runs left out the final RESULT: line the delivery contract asks for, so the app would show them as unverified. One PR body lost "$50" to shell expansion and read "exactly 0".
  • KT DOCSFive pages ran into the 32k-token output limit in repetition loops; one ky page is 16.5k words, mostly four bullets repeated.
  • KT DOCSQ&A answers averaged 112–187 words against Gemini's 276–359, and some stated the opposite of the code they quoted (the order of Flask's error-handler lookup).
  • CHATOne Flask explain run ended after a single call: the model handed the work to a sub-agent and never got a usable result back, so it answered nothing.
  • ALLThe model often calls tools by names from its own training (rg, read, cat, write). The agent rejects the call and the model corrects itself on the next turn, which costs a call each time.
  • CHATWhere it did well: it read the code before answering, re-ran its own tests, and never edited a file outside the one it was asked to write.
  • AUTOMATIONSWhere it did well: an exact triage fix (item.quantity ?? 1) that Gemini 2.5 Flash got wrong four times out of four, and a PR review backed by a real reproduction (expected 900, got 1000), which before only Gemini 2.5 Pro did.

How we tested

Model: RedHatAI/Qwen3-Coder-Next-NVFP4 (Apache-2.0, 4-bit weights) on vLLM 0.30.0 with native tool calling and a 128k context, on one RTX PRO 6000 Blackwell (96 GB) in Runpod Community Cloud. The endpoint is OpenAI-compatible and locked with an API key. NeoDevEx reaches it through an ordinary saved LLM profile, the same way it reaches Gemini.

Only the model under test changed. Each study ran its own harness unchanged, with a small wrapper that pointed the agent at the self-hosted endpoint and switched off provider features vLLM does not serve (prompt-cache flags, reasoning effort). Graders, judges, checklists, mutation tests and the KT neutral reader stayed on the models the original studies used. In the KT study, embeddings and search stayed on Gemini because the pod serves no embedding model. Runs cut off by the pod's hourly restart were re-run and not counted as model failures. Automations ran on a separate, isolated copy of the app. Each automation ran once; chat and token tasks ran three times each.

Not covered: the onboarding study, which was running on the same machine for another model at the time.
