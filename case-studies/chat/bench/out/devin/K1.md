Ky retries an HTTP error only if every check below passes. A server-provided wait (from Retry-After or one of its fallback headers) is capped only by maxRetryAfter. Ky's own computed backoff is changed by jitter and capped by backoffLimit. I checked out e0fcf78 and changed no files. All line numbers refer to Ky.ts unless another file is named.

1. When an HTTP error enters the retry path (Ky.ts:196-226)
Ky only creates an HTTPError when all of these are true: the response is not ok; it is not opaque (a no-cors response, which always shows status 0); throwHttpErrors is true (the default) or, if it's a function, returns true for that status. If throwHttpErrors is off, there's no error, so there's no retry. If the failing response came from a beforeRequest or beforeRetry hook rather than a real fetch (responseFromHook), the error is thrown without a retry. Otherwise #retryFromError → #calculateRetryDelay decides.

2. The retry decision, in order (#calculateRetryDelay, Ky.ts:504-590)
Limit: if retryCount >= retry.limit, the error is thrown. The default limit is 2, and passing retry: <number> sets only the limit (normalize.ts:16-34).
Method: the method must be in retry.methods (default get, put, head, delete, options, trace). POST and PATCH are not retried by default.
shouldRetry: if set, it runs next. false means no retry. true means retry with the computed backoff. This skips the status-code checks and ignores Retry-After. undefined falls through to the default logic.
Status code: the status must be in retry.statusCodes (default [408, 413, 429, 500, 502, 503, 504], normalize.ts:8-12).
Retry-After: handled as described in section 3.
413 special case: a 413 that doesn't use the Retry-After path is not retried. That happens when there's no header, or when 413 has been removed from afterStatusCodes.
Everything else that passed step 4 waits for the computed backoff (section 4).

3. Retry-After and its fallback headers (lines 553–575)
Header order: Ky reads the first header that is present, in this order: Retry-After, RateLimit-Reset, X-RateLimit-Retry-After (Symfony), X-RateLimit-Reset (GitHub), X-Rate-Limit-Reset (Twitter).
Statuses that use it: the header is used only if the status is also in retry.afterStatusCodes (default [413, 429, 503]). For example, a 500 or 502 that sends Retry-After ignores it and uses the normal backoff.
Accepted formats: Seconds to wait: Number(value) * 1000. Decimals work ("1.5" → 1500 ms), and "0" means retry immediately. Unix timestamp in seconds: a number whose millisecond value is at least Date.parse('2024-01-01') (that is, a value of 1,704,067,200 or more) is treated as a point in time, and the wait is that time minus Date.now(). A fixed cutoff is used to guard against clock skew. HTTP date: anything that isn't a number goes through Date.parse(value) - Date.now(), e.g. Wed, 21 Oct 2015 07:28:00 GMT.
Edge cases: Negative results (past dates or timestamps) are clamped to 0. A value that can't be parsed falls back to min(maxRetryAfter, computed backoff). An empty header value is falsy, so the Retry-After path is skipped. Because the chain uses ??, an empty Retry-After also stops Ky from checking the later fallback headers.
What applies to the wait: the server's value is used as-is, apart from the maxRetryAfter cap (default Infinity). No jitter and no backoffLimit are applied, which matches the jitter doc in retry.ts:69-80.

4. Computed backoff (#calculateDelay, Ky.ts:487-502)
The base delay is retry.delay(retryCount + 1). The default is 0.3 * 2 ** (attempt - 1) * 1000, i.e. 300 ms, 600 ms, 1200 ms and so on.
jitter (default undefined, meaning none): true gives full jitter: Math.random() * delay. A function gets the base delay and returns a new one. If it returns NaN, Infinity or a negative number, Ky uses the delay without jitter.
backoffLimit (default Infinity) is applied after jitter, so it caps the final value: min(backoffLimit, jitteredDelay). maxRetryAfter does not apply here.

5. Waiting and the other limits (#retryFromError, Ky.ts:852-928)
Every delay is clamped to maxSafeTimeout = 2,147,483,647 ms (constants.ts:58-58).
totalTimeout: if the delay is at least the remaining budget, Ky waits out the rest of the budget and then throws a TimeoutError instead of retrying.
The wait (delay.ts) can be cancelled only by the user's own abort signal.
beforeRetry hooks run after the wait. They can replace the request, return a Response, or return stop to end retrying.

6. Other paths, for completeness
Timeouts: retried only if retryOnTimeout is true (default false), using the computed backoff.
Network errors: retried with the computed backoff.
Other errors: unknown error types are never retried.
ky.retry() from an afterResponse hook (a ForceRetryError): it still counts toward limit, but skips the method and shouldRetry checks. Its delay option, if given, is used exactly, without jitter or backoffLimit (constants.ts:71-78).
