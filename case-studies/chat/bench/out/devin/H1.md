Hono's default router is a SmartRouter that tries RegExpRouter first and TrieRouter second. It holds every route until the first request, then uses the first router that can handle all of them and keeps only that one. I checked out 24547a6e and only read the code; no files were changed and nothing was run.

Where the default comes from
In src/hono.ts, the Hono constructor uses options.router if you pass one. Otherwise it creates new SmartRouter({ routers: [new RegExpRouter(), new TrieRouter()] }). That array order is the order the routers are tried.

1. When routes are added
app.get(), .on(), .all() and similar methods all go through #addRoute in hono-base.ts:385-396. It upper-cases the method, merges in the base path, and calls this.router.add(method, path, [handler, routeInfo]).
SmartRouter.add in smart-router/router.ts:13-19 just appends [method, path, handler] to a private #routes list. Neither underlying router sees a route at this stage.

2. On the first request
#dispatch (src/hono-base.ts line 419) calls this.router.match(method, path). SmartRouter.match (smart-router/router.ts:21-61) then works through the routers in order:
It replays every saved route into the current router with router.add(...) (lines 35–37).
It calls router.match(method, path) for the actual request (line 38).
If either step throws UnsupportedPathError, it moves on to the next router (lines 39–42). Any other error is re-thrown.
RegExpRouter builds its matchers lazily. Its add (src/router/reg-exp-router/router.ts lines 132–200) only records routes. The first match (matcher.ts) calls buildAllMatchers(), which compiles one big regular expression per HTTP method. So for RegExpRouter, the "can I handle these routes?" check happens inside step 2.

3. When and why it falls back
RegExpRouter puts all routes into one combined trie and builds a single regex from it, so some combinations of routes can't be expressed.
While building the matcher (buildMatcherFromPreprocessedRoutes, reg-exp-router/router.ts:34-65), trie.insert is called for each route. If it throws the internal PATH_ERROR, that becomes UnsupportedPathError(path) (line 64).
PATH_ERROR is thrown in node.ts:50-125 when:
two routes end at the same trie node (a second index for the same pattern);
a named parameter uses the regex .*;
a custom parameter regex contains a capturing group, e.g. (a|b); non-capturing (?:a|b) is allowed;
a new dynamic segment or a static segment would sit next to a different, non-wildcard sibling pattern at the same position. A single combined regex can't order those reliably.
UnsupportedPathError itself is defined in src/router.ts (line 103).
TrieRouter (trie-router/router.ts) walks a tree at request time and never throws UnsupportedPathError, so it is the always-works fallback. The partly built RegExpRouter is simply discarded. If every router failed, SmartRouter would throw Error('Fatal error') (lines 52–55), but with the default pair that can't happen.

4. After a router is chosen
In src/router/smart-router/router.ts (lines 46–58):
this.match is replaced with router.match.bind(router), so later requests skip SmartRouter's selection logic entirely.
The router list shrinks to just the chosen one, and #routes is set to undefined.
name becomes "SmartRouter + RegExpRouter" or "SmartRouter + TrieRouter", and activeRouter now returns the chosen router.
If RegExpRouter wins, its first match has already replaced its own match with a fast closure (matcher.ts). That closure checks a static-path map first, then runs the per-method regex. buildAllMatchers also frees its route tables and clears a regex cache (src/router/reg-exp-router/router.ts lines 208–222). Because the bind on line 46 happens after line 38, SmartRouter ends up pointing straight at that closure.
The [handlers, params] result is passed to Context. #dispatch then either calls the single handler directly or runs compose(...) over all of them (src/hono-base.ts lines 419–455).

5. Adding a route after the first request
SmartRouter.add checks if (!this.#routes). After the first match #routes is undefined, so it throws Error(MESSAGE_MATCHER_IS_ALREADY_BUILT), which reads "Can not add a route since the matcher is already built." (smart-router/router.ts lines 14–16; the constant is in src/router.ts lines 21–22).
The error reaches your app.get(...) call. In #addRoute, this.router.add(...) runs before this.routes.push(r), so the rejected route is also left out of app.routes. RegExpRouter has the same guard of its own (reg-exp-router/router.ts line 137), but SmartRouter's check fires first. The router is effectively frozen after the first request, so all routes have to be registered before the app serves traffic.
