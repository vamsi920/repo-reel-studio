What I did: on https://neo.neodevex.com with a real authenticated session, opened Knowledge (/kt) for vamsi920/layman and clicked into its CodeGraph tab; separately confirmed via the Supabase MCP tools (project hyirnyyqwyvplwvuekda) that `public.codegraph_snapshots` has a real row for this repo (4 nodes, 2 edges, created 2026-08-25) with a non-null `output_path`. Suggested fix: after `uploadArtifactsToStorage` finishes, verify the mirror actually landed (e.g. re-check `meta.json` and `levels/root.json` exist at the target prefix, or have `uploadArtifactsToStorage` return a success boolean instead of always resolving) before calling `saveSnapshot`, so the DB row is only ever written when the Storage copy it points to is real; alternatively, on read, distinguish "Storage mirror missing/corrupt for a snapshot the DB says should exist" from "no analysis has ever been run for this commit" and surface a clearer, more actionable error for the former (e.g. "This graph was built but its saved copy is missing — re-open the repository's conversation to rebuild it") instead of implying no analysis ever happened.
