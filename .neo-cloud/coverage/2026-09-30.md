## Whole-day test plan (codegraph)

### Core flows
1. [ ] Open a repo's CodeGraph tab for a commit that already has a real,
   previously-generated graph (Storage-mirror fast path via
   `openExistingAnalysis`) — confirm it loads without needing a live
   sandbox/conversation.
2. [ ] Drill down into a subsystem node (single-click / double-click per
   `codegraph-canvas.tsx`'s own dual-trigger design) — confirm the level
   loads and the breadcrumb trail updates correctly.
3. [ ] Click a node to open `CodeGraphNodeDetails` — confirm edges, siblings,
   and (when available) the `readSource` file-preview all render real data,
   and the panel closes cleanly via its own close control.
4. [ ] Toolbar type filter (`onToggleType`/`hiddenTypes`) — toggle a node
   type off, confirm those nodes disappear from the canvas and
   `visibleCount` updates; "Clear filters" restores them all.
5. [ ] Search box — type a real symbol/file name, confirm `ensureSearchIndex`
   loads `search.json` once (not on every keystroke) and results are
   relevant; selecting a result drills to its parent level and selects it.
6. [ ] Breadcrumb navigation — from a drilled-down level, click an ancestor
   crumb (and the root) to jump back up; confirm the canvas and toolbar both
   reflect the jump correctly.
7. [ ] "Build code graph" on a commit with no existing analysis — confirm
   the empty state shows, clicking Generate starts a live analysis, and
   progress phases (relationships/mapped) render sensible copy while running.
8. [ ] Rebuild button (`data-testid="codegraph-reanalyze"` on the stale
   banner, or the generic rebuild control) on an already-ready graph —
   confirm `keepOnScreen` behavior: the existing graph stays visible with a
   rebuilding indicator instead of the view tearing down to a blank spinner.
9. [ ] The `snapshot.owner/repo@commitSha` header line and file/symbol counts
   in the meta line — confirm they match the real repo being viewed, not a
   stale or wrong commit.
